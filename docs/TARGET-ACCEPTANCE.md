# 真实 Mac / Windows 验收清单（待用户环境运行）

本交付只在 Linux 容器运行真实进程/套接字测试。下列操作清单未被标记为通过，需在两台目标机器验证；交叉编译不替代原生执行。

## 1. 双机基线

在 Mac、Windows 分别运行对应程序 `version`，记录系统/架构/版本。按 README 建立 Mac Server、Mac Node、Windows Node；核对证书指纹、两个独立设备ID、真实 IP。跨网访问应遵守公司网络规则，不关闭整个系统防火墙作为“修复”。

验证 M1 升级：先备份旧数据，使用同目录启动新 Server；检查 schema2及 `metadata.json.v1.bak`，确认旧设备身份不变；需要回滚时恢复升级前完整目录而非混用新旧文件。

## 2. 必测 HTTP / TCP 闭环

Windows 回环运行 `python -m http.server 8080 --bind 127.0.0.1`；明确共享 `win-api` 并只授权 Mac 设备。Mac 将其映射到 `127.0.0.1:18080`，浏览器/curl访问内容与直接Windows访问一致；未运行的Windows端口应在有界时间内给出 `target_refused`。

下载较大随机文件，分别计算 SHA-256（Mac `shasum -a 256 FILE`；PowerShell `Get-FileHash FILE -Algorithm SHA256`）。同时建立多个连接，检查单流数据不串流。

验证数据库/调试服务或TLS目标时，使用 `share tcp`。业务登录、证书验证由原应用负责。只完成HTTP文件访问不等于所有TCP协议均通过。

## 3. 代理浏览器

Server启用独立7778；管理台7777登录后，在服务页“浏览器打开”。首次证书信任按本机策略办理；检查一次性表单登录、目标返回、活动记录；从另一台获授权设备重复。

验证SSE按事件逐条到达，WebSocket能建立并双向收发。用当前开发框架检查绝对资源、HMR路径、redirect；路径前缀不兼容应切换TCP映射，而不是静默降低认证。

需要Cookie/业务Authorization的项目应通过本地TCP映射验证；本版便捷Gateway刻意过滤这些字段。不在代理入口运行敌对/未知网页。

## 4. 权限与撤销

用未授权第三设备尝试 `proxy open`，应被拒绝且目标不建立可用业务流。尝试全网卡监听、非回环共享、URL代理，应被拒绝。

保持长连接，Owner修改ACL：已有流应结束，被移除身份新连接拒绝。保持长连接，分别撤销源设备、目标设备：现存数据流结束且旧凭证无效。Owner不带 `--allow-owner` 应不能直接代理访问。审计中有操作者/结果但无令牌或业务正文。

## 5. 恢复与故障

- 正常停止Windows Node：服务离线、旧流关闭、新流快速失败；重新运行后同一个Mac监听端口可建立新连接。
- Windows睡眠/唤醒、Wi-Fi切换、拔网线：未知失联在控制超时内显现；不得无限挂起。记录实际耗时。
- Server重启：旧流失败；Node重连；原Mac映射进程继续运行并重新注册租约。不得假称旧TCP字节被恢复。
- 主动 `proxy close`：监听进程退出，不自动复活。
- `services stop` 后重启Node：服务仍停止；只有本机再次明确共享可生成新服务。
- 本地端口已占用时，`proxy open` 即刻失败，不随机换端口冒充成功。

## 6. 原生和安全补测

Windows凭证目录ACL、Ctrl+C退出/文件锁、中文路径；Mac程序签名/公证与策略、证书信任、多网卡/SAN；IPv6回环（如需要）。使用当前受支持Go版本重建并跑race、漏洞扫描和协议安全评审。不要把开发版自维护WebSocket实现视作安全审计完成。
