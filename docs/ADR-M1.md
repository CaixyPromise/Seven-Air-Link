# M1 实施决策、差异与风险登记

日期：2026-10-28；版本：0.1.0-m1。依据原方案第 13 章的 M0/M1 定义，不提前把 M2/M3 算作完成。

## ADR-M1-01：依赖可用性与离线构建

本次容器具备 Go 1.23.2 / Linux amd64，但外部 Go 依赖源无法解析/连接。实际构建采用 `GOTOOLCHAIN=local GOPROXY=off CGO_ENABLED=0`，不要求评审者相信尚未执行的依赖下载。工程没有第三方 Go 模块。

代价是 M1 使用私有 `internal/controlws` 实现受限 RFC 6455 文本控制通道。它不是新的 Agent 协议，也不是完整隧道栈。支持握手、掩码、文本分片、UTF-8、ping/pong、关闭、有限帧长度与读写截止时间；拒绝二进制消息、扩展和压缩，累计文本上限 16 KiB。

已做异常帧单测、短时 fuzz、竞态检查，以及与独立 Python websockets 16.0 的双向互通。**这些测试不等于协议完整性认证或生产安全审计。**

M2 开发前须评审是否替换为可取得并锁定版本的成熟 WebSocket 库。不能直接把当前控制通道扩展成“已经可靠支持大流量、半关闭、背压”的数据平面。数据面 FIN/RESET、流控、并发、授权票据需要独立实现和测试。

## ADR-M1-02：当前元数据为 JSON，SQLite 延至 M3

原方案把 SQLite、消息/文件的完整接管列在 M3。本轮不为了没有实现的消息业务引入数据库，也不伪造一个 `sqlite` 文件名。

当前 `metadata.json` 包含 schemaVersion、Owner 身份 ID/令牌哈希、设备元数据及哈希凭证、短期配对码哈希、事件序号和最近 2,000 条操作元数据。每次授权变更先克隆候选状态、持久化成功后替换内存；失败不承诺成功。

Unix 临时文件 + fsync + 同目录替换及故障恢复已测试；Windows 文件替换及断电持久性还需原生验收。目录 fsync 为尽力执行。JSON 全量重写面向少量开发设备，不是高吞吐或无限历史方案。

M3 引入 SQLite 时须使用明确 schema migration，并保留旧 M1 元数据的备份与可回滚路径。原 Python 的 `state.json` 是另一种格式，不能与 M1 `metadata.json` 混用。

## ADR-M1-03：可信身份与运行态独立

Owner 是本机创建的人类管理身份；Node 使用独立 Device 凭证。Device 不等于 Human/Bot Principal。Bot 和多用户身份在 M3，本阶段不借 Device 凭证伪装成 Bot 接入已经完成。

长期授权落盘；在线连接、会话 ID 和心跳状态只在内存。Server 重启时不从磁盘恢复虚假的在线状态。每设备最多一个活动控制连接，重复连接返回冲突；同配置本机运行还受 OS 文件锁保护。

Node 前台常驻，不安装系统服务、不隐藏启动模型、不执行 Shell。管理员可撤销连接，但尚无远程主机操作接口。

## ADR-M1-04：TLS 默认开启且不自动接受新证书

默认生成 P-256 ECDSA 自签名证书，使用 Go 标准库实现。只提供 HTTPS/WSS，不提供 `--insecure` 或明文 LAN 模式。CLI/Node 必须固定信任 SHA-256 叶证书指纹；证书有效期与服务器用途也受检查。底层 `InsecureSkipVerify` 仅用于替换默认 CA/DNS 信任路径，配套的 `VerifyConnection` 必须执行精确指纹验证，不是跳过安全校验。

本方案信任的是具体证书，而不是公共 CA；首次配对必须由用户从可信 Server 终端核对指纹。证书不匹配时 Node 终止，不自行更新指纹。自动生成证书有效期为一年，本版不包含无感证书轮换。

证书 SAN 和 HTTP Host 白名单在初始化时固定；新增网卡/IP/域名可能要求正式证书更新流程。`--tls-host` 只在首次生成时生效，不能误导用户以为重启会自动扩充既有证书。M4 应实现受控轮换与信任更新。

## ADR-M1-05：默认资源边界

| 项目 | 当前值/行为 |
|---|---|
| 心跳 | 默认 5 秒，可配置 |
| 无有效心跳期限 | 默认 15 秒，至少心跳间隔 3 倍，最大 120 秒 |
| 受信设备 | 默认 64，配置上限 256；不是本次验证过的最大容量 |
| 未消费配对邀请 | 最多 64；有效期 1 秒～15 分钟 |
| JSON 请求 | 最大 8 KiB、禁止未知字段 |
| WS 文本消息 | 累计最大 16 KiB |
| 浏览器会话 / SSE | 会话最多 64，SSE 最多 32 |
| 登录/变更请求 | 同观察 IP 每分钟 60 次；多个设备共享 NAT 可能共同触发限制 |
| 活动记录 | 最近 2,000 条；非永久合规审计 |
| Node 重连 | 初始 0.5 秒、退避上限 8 秒，另加少量 jitter；稳定连接后重置 |

SSE 是持久事件的通知/重放通道，不替代授权检查。活动列表和 SSE 仅 Owner 使用；设备凭证仅能查询本设备与建立本设备控制连接。

## 必须公开的限制与发布门禁

1. Linux 独立进程故障验收通过不等于两台实体 Mac/Windows 网络验收；Wi-Fi 切换、系统睡眠、网关、防火墙及 Safari/Edge 仍待目标机验证。
2. 容器浏览器被管理策略禁止导航；完整 Browser E2E 被阻塞，未修改策略。离线 DOM 预览明确使用示例数据。
3. Go 1.23.2 仅为本次可用编译器。正式发布前使用受支持工具链、运行漏洞扫描和安全评审；当前没有完成在线漏洞库扫描。
4. macOS/Windows 二进制没有发布者签名/公证；跨平台通过仅指编译及文件格式检查。
5. Unix 凭证 0600 和目录 0700；Windows 使用当前用户目录和继承 ACL，未实现主动收紧 Windows ACL，需在原生环境检查共享用户目录风险。
6. Owner 的长期凭证、设备凭证均存于本地文件，无 OS Keychain/DPAPI 集成；设备可撤销，Owner 令牌/证书轮换尚无专用命令。
7. `/readyz` 检查已加载存储对应目录存在；不是磁盘空间/可写性的完整健康诊断。持久变更失败返回错误，不冒充成功。
8. 成功控制操作留痕，限频的鉴权失败也有元数据记录。审计写入失败会进运营日志；不承诺不可抵赖、永久完整或主机级全量审计。
9. 一台 Server 单点；无共享 SQLite、多主、HA、P2P、NAT 穿透、远程 Shell。

这些限制不妨碍先验证受控的 M1 开发链路，但禁止把此版本直接标成“生产就绪、跨平台全部验收通过”。

## 证书选择复核依据

互通测试首先验证 Go/Python 客户端，不能据此推断浏览器的证书算法支持。P-256 ECDSA 是本项目的保守互操作选择；仍需浏览器实测。参考 TLS 1.3 的签名算法定义：https://www.rfc-editor.org/rfc/rfc8446.html 。不同浏览器对 Ed25519 证书的支持不可由 X25519 密钥交换支持推出；Mozilla 的相关实现说明：https://bugzilla.mozilla.org/show_bug.cgi?id=2037389 。
