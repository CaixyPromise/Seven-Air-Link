# M2 开发接续基线

M0/M1 已提供可运行 Server/Node、固定证书信任、设备身份、可观察的在线/离线与撤销、统一 HTTP 契约，以及可复跑的真实进程故障测试。本文件只定义下一阶段，**没有宣称任何网络转发已经实现**。

## 第一个验收目标

Windows 的 `127.0.0.1:8080` 经已配对 Node，被 Mac 上 `127.0.0.1:18080` 访问；无需把 Windows 服务监听到全部网卡。链路完成授权、生命周期、数据正确性和失败语义，再加便捷 HTTP 入口。

## 按顺序实现

1. 对 M1 私有控制 WebSocket 的复用/替换作正式评审，取得成熟依赖并锁定版本后可替换 transport；保留设备身份、生命周期和黑盒测试。不要因 M1 的独立互通通过就省略数据面评审。
2. `Service` 注册与服务级授权，先仅允许共享者本机回环目标；网页意图不能绕过 Node 的本机批准。业务 Principal 与 Device 分开，不能临时把 Device 永久当用户。
3. `share tcp/http` 和 `proxy open` 的明确语义：share 是登记本机服务，proxy 是调用者本机监听。默认回环，端口冲突立即失败；不偷偷常驻。
4. 一条 TCP 流一组专用数据通道、短期一次性票据、双方身份/服务绑定、建连超时、关闭传播。与控制 WS 分离；有界缓冲和背压、FIN/RESET 半关闭、不记录业务数据内容。
5. 通过 HTTP、随机二进制、TLS-over-TCP、长连接测试，再实现 `httputil.ReverseProxy` 经授权 Dial。验证 SSE/WebSocket Upgrade/重定向；路径前缀无法适配时明确推荐本地端口映射。
6. 原 M1 故障测试继续作为回归：Server 重启、Node 失联、撤销、错误 pin、双节点隔离不得退化。

## M2 新增验收，不能提前打勾

- 两个真实目标操作系统上的 localhost 互通；同 Linux 模拟仅作为开发测试。
- 20 条持续 TCP 流的字节正确性和并发资源基线；探索 50 条而非先承诺性能。
- 撤销后拒绝新流、关闭存量流；已知离线快速失败、未知失联有界失败。
- 目标拒绝、连接超时、监听冲突、半关闭、慢消费者、服务端重启可解释。
- 服务授权与 Node 本机授权双方成立；任意 URL/地址代理、未批准监听全网卡被拒绝。
- TCP 数据不写进消息/审计；仅记录必要操作元数据。

## 不引入的东西

不增加 A2A、Agent Adapter、模型识别、Agent Task Runtime、默认远程 Shell、UDP、VPN 或 HA。Bot 在后续阶段以统一身份通过 CLI 进入，不需要 Bridge 理解对端模型。
